# 多账号上游资源池

四类上游统一接入：Fish、Deepgram、OpenAI 兼容 LLM、SiliconFlow STT。
管理入口为 **Admin → API 与密钥**。保持现有单进程、SQLite 和 2C2G 部署，
不需要 Redis 或额外网关。应用不注册账号、不领取赠金、不自动充值。

## 添加和使用

1. 点击对应提供方的“＋添加账号”，填写名称、Key、端点和模型。
2. 配置真实的共享配额归属。不同 Key 若属于同一账号/项目，应选择同一配额组；
   相同 Key 跨模型添加时默认共用配额，不能按 Key 数量计算并发。
3. 新资源默认并发 1。根据账号实际额度设置并发、RPM、可选 TPM、日/月请求上限。
   默认上限 0 表示没有额外的本地限制，不代表供应商没有限制。
4. 点击“保存并验证”：先加密保存为待验证，执行一次小型业务请求；通过后参与调度。
   验证可能使用少量供应商额度，但不会一次性探测全部账号。
5. 提供方首次验证成功会启用池；如果管理员曾显式回滚到单 Key 模式，之后再次验证
   不会自动推翻回滚选择，需要主动启用池。

LLM 严格同模型分组，不自动更换聊天模型。新建其他模型的池后，在折叠的
“旧配置、模型默认设置与回退”中切换默认模型；已经验证过的池不会再用旧 Key
测试这个模型。建议模型也单独匹配其配置的模型组。

Fish 按同一模型和目标音色挑选账号，不能用另一个人的音色代替。高级设置中的
“音色 ID”使用精确列表；为空表示能力未知，实际权限错误会隔离该账号与音色的
组合。验证一个短句不等于验证了全部角色音色。

Deepgram 在建立识别连接时选择账号，整个连接固定绑定；不会在一句话或一通电话
中途换账号，也不预开大量空闲 WebSocket。原有实时电话默认上限仍为 3 路。

## 调度与资源限制

资源配置、共享配额组和同模型路由组分开管理。HTTP 任务按如下分数选择额度组：

`(组内在途数 + 1) / 组并发上限 × EWMA 处理耗时`

EWMA 系数为 0.2；业务探测提供初始样本。组内再挑可用凭据，分数相同时优先暖
连接、再轮转。Deepgram 长连接按连接占用率选择。组和成员均建立内存索引，
共享组的多把 Key 不会增加该组的权重或总并发。

保存账号数量没有业务硬上限，列表每页 25 条；不会为所有账号预创建客户端。
配置元数据仍随账号数量增长，实际存储数量受磁盘和内存约束；验证覆盖了 1,000 条
资源配置，并不表示有限硬件可以加载数学意义上的无限账号。
默认本机总保护独立于账号数量：

| 配置 | 默认 | 含义 |
| --- | ---: | --- |
| `SE_CHAT_CONCURRENCY` | 32 | 前台聊天在途任务 |
| `SE_CHAT_QUEUE_SIZE` | 64 | 前台等待任务 |
| `SE_PROVIDER_HTTP_LIMIT` | 32 | 所有上游的在途 HTTP 请求 |
| `SE_PROVIDER_WS_LIMIT` | 16 | 上游 WebSocket 连接 |
| `SE_PROVIDER_QUEUE_LIMIT` | 64 | 上游调度等待任务 |
| `SE_PROVIDER_CLIENT_LIMIT` | 16 | 懒加载 HTTP 客户端缓存 |

整轮聊天仍受 30 秒期限和每用户一个生成任务约束。切换账号、重试或兼容性回退
不会重置期限。旧 `SE_FISH_CONCURRENCY`、`SE_LLM_CONCURRENCY`、STT 单池限制继续
管理单 Key 路径；启用相应模型池时由账号/额度组和上述本机限制接管。

401 隔离失效凭据，额度耗尽停止分配，429 遵循冷却时间；连续三次临时服务错误
进入 30 秒熔断，半开只探一个请求。HTTP 明确拒绝且没有输出时最多尝试两个候选。
结果不明的超时或已经输出文本/音频的请求不会盲目重放。

每次实际 HTTP 尝试单独申请租约，包括参数兼容性重试。预算在派发前保守预留，
取消或连接失败也可能保留该次预留，因此不是供应商的精确账单。日/月计数按 UTC
持久化，重启不能清零。LLM TPM 使用保守估算，有实际 usage 时校准；流式 usage
未知时保留估算，不写成 0。赠金金额、余额和到期时间不会从账号名称或型号推断。

## 热更新、暂停与删除

- 改 Key、端点、模型或能力后必须重新验证，即使资源当时已暂停。
- 暂停只停止新派发；运行中的任务保持其旧凭据和版本，正常结束。
- 在途资源的配额组改动会提示先暂停并排空。底层也会延后直接配置改动，
  不把旧组的在途负载错误地算成新组的空闲名额。
- 删除采用排空，最后一个租约释放后清理；重启不会重新导入已删除的旧配置副本。
- 管理台断线或请求取消，已提交的配置仍会完整更新运行时快照，避免数据库已改
  而旧密钥继续接收任务。过期验证和并发编辑返回冲突，不能激活新版本。
- 显式回滚按提供方独立关闭池，恢复原有单 Key 路径。已激活池暂时不可用时，
  不会偷偷绕过它调用旧 Key。

## 密钥、迁移和部署

新增凭据使用 Fernet 加密存入 SQLite，页面和查询只返回指纹。默认主密钥保存在
`data/provider-master.key`，Linux 权限 0600；也可用 `PROVIDER_POOL_MASTER_KEY`
注入已有 Fernet 主密钥。**数据库和主密钥应分别备份，丢失主密钥不能解密凭据。**
`data/` 和临时验证目录均被 Git 忽略。

启动仅将原有配置一次性导入为待验证项，不调用真实供应商，也不改变当前路由。
验证并启用池后，业务才会使用池。原文件保留供回滚；迁移标记阻止删除的导入项
在重启后重新出现。管理 API 复用现有管理员鉴权、CSRF 和字段级审计。

部署步骤：

1. 备份 SQLite（使用 SQLite backup API）及相关配置。
2. 安装更新后的 `backend/requirements-cloud.txt`；新增依赖 `cryptography>=43`。
3. 在开发机运行 `npm run build:backend`，将构建产物随代码部署到服务器。
4. 检查上表环境变量；已有值会覆盖新默认值。保持一个 Uvicorn worker，配置现有
   管理台密码/Token 并确认反向代理访问控制。
5. 重启服务，确认旧模式可用，再逐类验证资源并启用池。
6. 验证正常聊天、语音、识别连接、暂停排空和回滚。实际账号并发、余额及使用条件
   应单独确认；本机离线测试不能证明某个真实账号拥有独立额度。

## 离线验证

测试全部使用合成 Key 和回环假上游，网络审计钩子阻止外部连接。
执行多账号持续负载示例：

```sh
python scripts/perf/smoke.py --out-dir .tmp/pool-soak-new --users 100 --history 20 --duration 1800 --rate 3.3333333333 --mode arrival --max-inflight 100 --fish-base 3 --fish-per-char 0 --fake-concurrency 0 --pool-fish-accounts 3 --pool-fish-concurrency 5 --pool-llm-accounts 3 --pool-llm-concurrency 10 --maintenance
```

输出目录必须尚不存在。`fake-concurrency=0` 关闭的是假上游的总额度，
每把合成 Key 的 5 路限制仍独立生效。报告同时记录后端池和假上游的总峰值、
逐账号峰值、429、实际发送率、可解码音频和整机/进程树资源信息。
源码指纹与配置一起记录；运行于开发机的假上游结果不等于真实 2C2G Linux 验收。
